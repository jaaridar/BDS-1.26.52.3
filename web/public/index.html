OpenBDS · world generation

Bedrock seed finder

Type a seed range and say what the world must contain. Every position is computed from the placement algorithm recovered from the Bedrock dedicated server — no server, no download of world data, no lookup table. The same algorithm is in this repository as src/world/, and this page runs a WebAssembly copy of it that is checked against that code before every search.

Not available as filters

These sets exist in the game but their placement is not measured, so a filter on them would guess.

  • abandoned camp — pack placement; no captured positions yet, so the engine is inferred from the other pack sets
  • desert pyramid — placement parameters are placeholders, not measured
  • igloo — placement parameters are placeholders, not measured
  • jungle temple — placement parameters are placeholders, not measured
  • mineshaft — per-chunk frequency placement; the gate threshold is not recovered yet
  • ocean ruin — placement parameters are placeholders, not measured
  • witch hut — placement parameters are placeholders, not measured

Biomes and terrain are also absent, because the climate sampler is not recovered.

Stronghold placement, and the part of it that is still open

Strongholds sit on a 200-chunk cell grid. A cell's third random draw against 0.25 decides whether the stronghold stays at the cell's grid position; when it does, the position is exact — 491 of 510 gated cells in the captured corpus, and 159 of 160 when the server was asked about the model's own predictions — and cells that fail the gate were never at their grid position (0 of 82, and 0 of 160).

Every world also contains exactly three more strongholds, placed at villages, and the rule that picks those three villages is not recovered yet. This page therefore reports the grid strongholds only, and counts them as “on-grid”. The villages those extra three use are known positions — only the choice is missing. See docs/worldgen.md.

Why there is no biome filter

Biomes in Bedrock come out of a climate noise router, and its density function and climate mapping have not been recovered yet, so no surface biome can be predicted from a seed. The biome data (76 biomes with their climate targets) is loaded in the repository, but data is not a sampler.

A biome checkbox would therefore have to invent answers, so there isn't one. The filters offered here are the ones whose parameters were confirmed by asking the server and matching every captured answer.

What is exact, and what is not

A filter is offered only when its parameters were confirmed against captured server answers. Confirmation means every captured position of that set was replayed and matched; the tally is in src/world/structures-data.js and the method in docs/worldgen.md.

Coverage of the structure model
Structure Status Evidence
villages, outposts, monuments, mansions, shipwrecks, ruined portals, ancient cities, buried treasure Exact Every captured position reproduced; parameters unique over the fit
trail ruins, trial chambers Within one chunk Pack placement replayed on the Java engine; reported positions are structure origins
strongholds (on grid) Exact 491 of 510 gated cells matched (159 of 160 when asked directly); 0 of 82 ungated cells did
strongholds at villages Not modelled Three per world, always on a village; the choice of village is open
ocean ruins, desert pyramids, jungle temples, witch huts, igloos, mineshafts, abandoned camps Not offered Parameters are placeholders or the set is gated per chunk
biomes and terrain Not modelled The climate sampler has not been recovered

Every block of every world is not predicted yet, so this is not a whole-world generator: it is the structure half of one, with its gaps listed above rather than filled in.
